## Media step two phases — AI queue + 4 parallel lanes (2026-11-03, CEO law)
- The AutoPanel media step no longer generates AI inline during determination. `fillOneMediaTarget` was split into `searchMediaForTarget` (search only: Wikimedia → stock, pick on success) and `generateAiForTarget` (AI generation only). Phase 1 walks every scene/part doing search-only determination; any target with no passing candidate is pushed onto an in-run AI queue (with a panel message per queued item) and determination continues with the next scene/part. Phase 2 drains the queue in bulk with a worker pool of at most 4 concurrent `generateAiMedia` calls, logging progress (x/N) and a success/failure summary; generation failures join the existing failures/needs-manual flow, and the genimages fallback + still-missing scene check afterwards are unchanged.
- Concurrency safety on the server: `pickMedia` and `generateAiMedia` in privileged.ts used to read the plan, await slow work (download / media generation), then write the whole plan back — parallel calls would clobber each other. Both now compute the (deterministic) target file name up front, do the slow work outside any lock, and perform only the re-read → mutate → write step inside a per-project promise-chain lock (`withPlanWriteLock`). No factory data format changed.
